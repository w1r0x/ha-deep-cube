# Release 1.0.0

Date: 2026-10-01.

## Task

Publish the first release of the unofficial Home Assistant integration for the deep sleep cube, installable through HACS as a custom repository and usable in any interface language.

## Solution

### Layout of `custom_components/deep_cube/`

| File | Role |
| --- | --- |
| `protocol.py` | Command encoding and reply parsing. No Home Assistant or BLE dependencies |
| `client.py` | One short BLE connection: reads, settings, start with verification, stop. Depends only on `bleak` and `bleak-retry-connector` |
| `coordinator.py` | `DataUpdateCoordinator`: polling, commands, the parameters of the next start |
| `config_flow.py` | Bluetooth discovery, manual choice among cubes in range, options (polling interval) |
| `select.py`, `time.py` | Program, intensity and wake-up time of the next start; restored after a restart |
| `switch.py` | The main switch of the cube and the three cube settings |
| `sensor.py` | Current program, program end, battery |
| `services.py`, `services.yaml` | `deep_cube.start_program`, `deep_cube.stop_program` |
| `diagnostics.py` | Diagnostics without the cube address |
| `strings.json`, `translations/en.json`, `translations/ru.json`, `icons.json` | Interface texts and icons |

### Behaviour

- Every poll and every command is a separate connection: connect, do the work, read the full state, disconnect. A lock keeps the operations from overlapping. The cube is looked up through the Home Assistant Bluetooth stack, so local adapters and ESPHome proxies both work, and the official app stays usable.
- The main switch has no name of its own and is shown under the device name: on starts the selected program until the wake-up time, off stops the running program.
- A start first stops a running program, sends the start command and then checks the status up to three times. If the program is not running, the user gets an error: the "accepted" reply alone proves nothing.
- A stop is not sent when nothing is running, because the cube answers it with an error.
- The wake-up time is converted into a duration in the Home Assistant time zone; the subtraction is done in UTC so that a daylight saving change during the night does not shift the result.
- Polls use 2 connection attempts and commands use 3: a failed poll is repeated at the next interval anyway, and fewer attempts shorten the startup delay when the signal is poor.
- Changing the polling interval does not reload the entry and does not connect to the cube.
- Intensity and the three cube settings are hidden by default: they are available on the device page but stay off automatically generated dashboards.
- The "Program end" sensor ignores shifts within the accuracy of the cube's elapsed counter (steps of 1/1000 of the duration).

### Languages

All interface texts are in the translation files; the code only holds keys. Entity states are language-independent identifiers (`just_sleep`, `low` and so on). English and Russian are shipped; another language is one more file in `translations/`.

### Scope

- deep.r is tested (firmware 1.8.9). deep.n is discovered and driven with the same protocol but is untested.
- Four programs whose identifiers were observed in the official app traffic are supported.

## Files

- `custom_components/deep_cube/` — the integration.
- `hacs.json` — HACS metadata; minimum Home Assistant 2025.2.
- `docs/protocol.md` — BLE protocol description.
- `tools/` — debugging scripts for a PC.
- `tests/`, `pytest.ini`, `requirements-test.txt` — tests of the protocol module and of the translations.
- `.github/workflows/validate.yml` — tests, hassfest and HACS validation.
- `README.md`, `README.ru.md`, `LICENSE`, `AGENTS.md`.

## Checks

- `pytest` — 40 passed. Start commands are compared byte for byte with the ones the official app sent.
- `client.py` against a real deep.r over direct Bluetooth: versions, battery, settings, setting toggle and restore, start, start over a running program, stop, stop when idle — all as expected.
- On Home Assistant 2026.9.4 through an ESPHome Bluetooth Proxy: discovery and setup, entities and their Russian names, settings, selections surviving a restart, start and stop with the switch and with the actions, rejection of an unknown program and an unknown device, options flow, diagnostics.

## Known limitations

- With a poor signal commands may need a repeat, and the first connection at startup can take tens of seconds.
- While the deep up app is connected, the cube is unreachable and the entities are unavailable.
- The switch stays on for up to one polling interval after the program ends by itself.
- deep.n is untested. Other deep.r programs are not supported.
- The English program names are the author's translation, not official ones.
- hassfest and the HACS validation run on GitHub after a push; they were not run locally.

## Rollback

Remove the integration in Home Assistant (**Settings → Devices & services → deep sleep cube → Delete**), delete `custom_components/deep_cube` from the configuration folder and restart Home Assistant.
